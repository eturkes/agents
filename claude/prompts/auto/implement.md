# Implement

Use: ITERATE go, a route, or a scope opening directly at IMPLEMENT. Template files absent → copy them in (README `Template files`). Fresh session at the project root + advisor on (README `Advisor`) → paste everything below the rule.

---

Implement the intended software for the scope in `.agent/spec.md` `Phase`; set `Phase: IMPLEMENT — <scope>` first. `Intent` outranks everything here, `Decisions` bind; `Intent` + `Decisions` = the direction to build, its design chosen anew; a prototype in `Artifacts` = its illustration, its details binding only through a `Decisions` entry or my request; a shipped repo keeps the behavior `Decisions` leaves alone. Global + project `CLAUDE.md` law applies as written, `Session flow` IMPLEMENT first; where a `.claude/rules/` ruling adapts or retires a structure below (gate, CI, ledger, prototype), that ruling governs the step. MAINTAIN follows in order — `Dependency upgrade`, `Code review` (teammate-run, blind), `Security review`, `Queue` ⇒ version bumps past the stack choice, blind review + `.agent/deferred.md` rows wait for them; your closing message names those four bodies in that order.

1. Interpretation per `Session flow` IMPLEMENT orientation: each `Intent` clause → a testable reading, each prototype aspect → `ruled` | `incidental` | `unclear`; ambiguities join step 2's `AskUserQuestion`; confirmed readings → `Decisions`.
2. Stack: chosen anew, best in class — a prototype's stack competes like any other; a shipped repo keeps its stack unless `Decisions` or I reopen it. The stack + every decision costly to reverse → teammates, then the advisor, per `Session flow` IMPLEMENT orientation. Every open tooling or method question → SOTA survey + spikes; select for task + agent fit + SOTA over popularity; my preselection wins. One `AskUserQuestion` for the stack + every spec gap, step 1's ambiguities included, before files that encode them; ask again whenever direction is unclear. Plan the units in `Tasks`, then the plan's pre-mortem + the acceptance and characterization suites (`Session flow` IMPLEMENT orientation).
3. Foundation, for whatever the repo lacks: package metadata (project name + `LICENSE` identifier), entry point, one passing test, every gate wired — format, lint, type-check, test, `.agent/spec-lint` (a template file), a tree-clean check (the gate leaves `git status --porcelain` as it found it ⇒ ignore coverage holds) + the scanners below — behind one gate command whose invocation lands in `.claude/rules/<topic>.md`. What already runs stays and is extended.
4. Security scanning, automated + committed: dependency vulnerability audit, secret scan, static analysis for the stack, in the gate command and in CI (`.github/workflows/` or the host's equivalent), plus update automation (Dependabot/Renovate) where the host supports it.
5. Units: each declares its tier + a contract of testable predicates before code; gates green at every commit, one scoped commit per unit, `Tasks` ticked.
6. Review, led by you with the build in context — MAINTAIN's reviews follow blind ⇒ weight what only the author holds: intent behind each choice, shortcuts + stubs taken, cross-unit interactions, claims in commits + docs; teammates only where the review outruns you alone: the whole diff per declared lens (correctness/spec, claim soundness, guarantee-vs-claim gaps, verification integrity, `CLAUDE.md` conformance), check set fixed before reading, each finding proven by a red test; you adjudicate every row in `.agent/review.md` (committed as rows close); accepted fixes land before close. `CLAUDE.md` conformance lens = one row per clause of every repo `CLAUDE.md` + `.claude/rules/` file that binds a tracked file — a clause a tool can decide → its gate check runs + fires on a planted bad input, none → a finding fixed by wiring the check (`Engineering`). Security lens, yours alone (security vocabulary ends a teammate's context): each untrusted input in remotely reachable code traced to every sink it reaches, against the repo's own validation + auth patterns — injection (SQL/NoSQL, shell, template, XML entities, file paths), authn/authz bypass + privilege escalation, session + token handling, secrets + crypto (hardcoded keys, weak algorithms, randomness, certificate checks), unsafe deserialization + eval, raw-HTML sinks, server-side requests to attacker-chosen hosts or schemes, data exposure (secrets + PII in logs, debug output, API responses); trust model: env vars + CLI flags = trusted, the server = the enforcement boundary, framework auto-escaping holds outside raw-HTML sinks; its findings = rows with the rest.
7. README in the human-facing register: install, run, configure — current for everything the scope ships. Retire each disposable prototype `Artifacts` names for this scope: `git tag prototype-<scope>`, then `git rm -r` its path, or move a still-useful aid under `tools/` and record it in `Artifacts`.
8. `.agent/spec.md`: `Artifacts` = the implementation's entry points + run commands, `Decisions` + `Tasks` current, `Phase: MAINTAIN` with the scope folded into the whole product — a waiting `Suspended:` scope's phase instead (`Session flow` Routed state).

Met when: the full gate command (scanners included) passes on a clean working tree at the closing commit, CI + scanning + update automation are committed, every `Decisions` entry is implemented with its acceptance tests merged + green, or moved to `.agent/deferred.md` with its reason, `.agent/review.md` holds no open row, every disposable prototype of the scope is retired, and `Phase: MAINTAIN` (or the resumed suspended scope's phase) is committed — each structure a `.claude/rules/` ruling adapts or retires is met through what that ruling names.
