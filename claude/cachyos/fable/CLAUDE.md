Each rule = live law + the why a fresh agent would otherwise re-derive; its origin story (incident, discovery, commit trail) → the commit body that lands it; a multi-step recipe → a committed script the rule names.
- Human-facing = surfaces a person reads at consumption time: shipped README + docs, UI copy, CLI help…; machine-consumed payload (JSON fields, logs, codes) = code surface. ## Engineering

- Elegant, tightly-scoped modular components; deduplicate; KISS + UNIX where apt; refactor proactively.
- Code = agent-read artifact → concise within three bounds: performant, bug-free, maximally agent-legible. Idiom serves human readers → keep the idiomatic form where it also serves those bounds.
- Comments cost tokens → spend them on the `why` fresh agents would otherwise re-derive every pass: the constraint, measurement, or upstream quirk behind a peculiar decision. Code states the `what` on its own.
- Target sufficient scope, evidence-backed claims, and real success criteria.
- Established methods (TDD red-green-refactor, differential oracles, adversarial review) + any practice that measures better than the training-data default; unconventional is fine where it wins.
- Research, whenever a tooling, method or design choice is open = your knowledge + `WebSearch` + verbatim page text (`webtext`) + the signed-in browser (`Environment`) for authenticated + paywalled sources — journals, x.com, GitHub issues + discussions, forums, vendor docs; past a few sources, `researcher` fits (`Subagents`). Primary sources + measurements outrank popularity.
- Open tooling decisions (language/library/package…) → research (above) + select for SOTA task/agent fit; my preselection is authoritative. Training overweights human-popular convenience; library availability alone = insufficient — code is cheap, reimplementation viable. Consider agent-oriented languages (agentlanguages.dev) + AI-targeted tooling; build on mature work where it is genuinely SOTA.
- Deterministic checks own every rule a tool can decide: linters, type checkers, static analysis, formatters, schema/contract validators; judgment passes spend on what no tool decides. Configure + extend proven checkers first; uncovered invariant → purpose-built check wired into the gate, shipped with the input that makes it fail and its firing recorded in a `paths:` rule on the check's files; a check that cannot fail and a clean tree emit the same green.
- Tests/verification: derive scope from requested outcome + regression risk + repo posture. Add coverage that accelerates delivery or protects behavior. Fuzzing/property/formal methods require a task-specific advantage.
- Runnable change → run the real app by its recorded command + drive it to the changed behavior, beyond the gate: CLI = representative invocations, exit code + output; server = a request to the route the diff touches; TUI = keystrokes in, screen out; UI = a screenshot, inspected (blank frame = failed launch); library = an import-and-call smoke at the package boundary. A launch alone or tests alone leave the change unrun.
- Verification integrity binds every check on the implementation. A test counts once seen red on the unfixed revision, that revision + command recorded in the unit's commit body; a test pinning behavior that already passes counts once the stack's mutation tool (default operators, scope = the files the test imports or calls) shows it killing their mutants, scope + command + every survivor recorded in the commit body. An implementation satisfies its contract across the whole input domain → test/gate detection, a fixture's expected value returned + an expected-output table the contract does not own = defects. Each unit keeps its grading check unchanged; a threshold, case or gate changes only in a unit I approve, recording the original check's firing. A skipped, xfailed, deleted or tier-demoted case earns a deferral row + my approval first. `green` names checks run + passed; skipped, not-run + missing checks report by name or `none`.
- Assurance tier, declared per unit with its contract: `kernel` (judgment-bearing code/spec) = full adversarial battery; `data` (consumer re-validates at use) = one structural validator + live spot-check, defects fix forward; `docs` = consistency pass. Deciding question: where does a defect get re-checked for free, at what cost? Rigor concentrates where no downstream re-check exists.
- Units = the shortest path to the consumable artifact, and that alone. Off-path improvements are born as deferral rows (a project's deferral queue), acceptance check written at deferral time while evidence is fresh.
- A gate backing a durable claim must rerun from committed state; scratch-local validator = temporary encoding → record its regeneration path in a `paths:` rule on the files it validates + schedule the port as a deferral row.
- Repairs to a generated artifact land as one idempotent script replayable from a clean base → the wave stays re-derivable; credit by rerunning to byte-identical output.
- Adversarial review (code or session) → scrutinize correctness + logic, claim soundness, guarantee-vs-claim gaps; weigh honesty + overreach above style.
- Code diff lenses = the author's self-review before each commit + the default rows of any code check set, one pass per lens. Correctness: each hunk read with its enclosing function; each deleted line's invariant holds elsewhere; callers + callees of each changed function still fit; moved code keeps its guards + anchors; the language's classic pitfalls ruled out; wrappers route to the wrapped instance; config defaults change only by intent; test setup + teardown stay symmetric. Cleanup: existing helpers reused (grep before writing one); derivable state computed, never duplicated; near-duplicate blocks merged; dead code removed; independent steps parallel; startup + hot paths lean; closures capture only what they use. Altitude: a special case on shared infrastructure signals a fix due in the mechanism. Cleanups preserve behavior; gate after.
- Split assurance by what it costs the decider: mechanical checks (suites, differential oracles, validators) cost a rerun → inline with the work; judgment adjudication costs attention → its own pass after implementation, resumed across compactions + sessions against a committed ledger. Whatever shares a window with implementation is what an overrun drops.
- Review terminates on a check set fixed before the diff is read: adjudicate every row, ship the table, count rows adjudicated as the deliverable — an all-`pass` table is a complete review. Findings bind to the artifact's acceptance contract; everything outside it reports as a register entry. An accepted ruling holds until new evidence reverses it, and a fix earns one re-review round against its acceptance check alone. Model opinion drifts run to run, so an open-ended review→fix loop flip-flops, creeps scope + injects defects — the fixed set + evidence bar (`Subagents`) are what make it converge.
- Delegated reports are two-tier: a verdict table the decider always reads, over detail sections keyed by row id, opened per row needing a ruling. Harvest cost tracks what the decider reads ⇒ the table is the budget.
- Remotely-exploitable code → highest security standard: periodically audit, update software to latest, verify behavior after.

Fits below (+ project `Session flow` phase fits), each with its reason, weighed per `Offload economics`:
